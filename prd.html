1. Executive Summary & Product Vision

Royal Ludo Online is a premier, real-time multiplayer board game engineered for web and mobile browsers, combining the nostalgia of classical Indian Pachisi / Ludo with high-stakes royal aesthetics, competitive wagering tiers, multi-device WebRTC/Supabase voice chat, deterministic state synchronization, and intelligent tactical AI bots.

1.1 Core Value Proposition

  • Authentic Mobile Gaming Feel: Tailored specifically for portrait smartphone screens with responsive 100dvh viewport constraints, rich royal blue textures, and touch-optimized controls matching Ludo Star and Ludo Club standards.
  • Flexible Dynamic Player Capacities: Seamlessly supports 2-Player Duels, 3-Player Chambers, and 4-Player Matches in private rooms without phantom bot stalls or turn lockups.
  • Competitive Stake Wagering: 5-tier Table Bet Stakes (500 to 250,000 Coins) with real-time pot deduction, dynamic pot collection HUD, and automated 100% winner payouts.
  • Smart Single-Piece Auto-Progression: Instant 420ms auto-walk algorithm whenever only 1 token has a legal move, eradicating redundant taps.
  • Integrated Multi-Device Voice Chat: Cross-platform Web Audio API capture with real-time Supabase Realtime Broadcast synchronization and live speaking ripple visualizers.

3. Ludo Engine Mechanics & Game Algorithms

The game engine (src/lib/ludo/engine.ts) is implemented as a pure, deterministic, state-machine capable of server-authoritative validation.

3.1 Board Geometry & Coordinate Space (15x15 Matrix)

  • Total Grid Size: 15 rows × 15 columns (0..14 index coordinates).
  • Main Circuit Track: 52 distinct outer track cells (indices 0..51).
  • Home Path Steps: 5 private sanctuary cells per seat (steps 52..56) culminating in the center Victory Goal (step 57).
  • Total Progress Steps: Exactly 57 steps from base unlock to goal.
Player Seat Color Base Corner Start Track Index Home Column Range Entry Track Cell
Seat 0 Red Top-Left (0..5, 0..5) Index 0 (Row 6, Col 1) Row 7, Col 1 → 5 Index 51 (Row 6, Col 0)
Seat 1 Green Top-Right (0..5, 9..14) Index 13 (Row 1, Col 8) Row 1 → 5, Col 7 Index 12 (Row 0, Col 8)
Seat 2 Yellow Bottom-Right (9..14, 9..14) Index 26 (Row 8, Col 13) Row 7, Col 13 → 9 Index 25 (Row 8, Col 14)
Seat 3 Blue Bottom-Left (9..14, 0..5) Index 39 (Row 13, Col 6) Row 13 → 9, Col 7 Index 38 (Row 14, Col 6)

3.2 Safe Havens & Immunity Rules

Tokens situated on safe havens cannot be captured by any opponent under any circumstances:

  • 4 Starting Cells (Shield Crests): Index 0 (Red Start), Index 13 (Green Start), Index 26 (Yellow Start), Index 39 (Blue Start).
  • 4 Classical Star Cells (⭐ Glyph): Index 8 (Row 2, Col 6), Index 21 (Row 6, Col 12), Index 34 (Row 12, Col 8), Index 47 (Row 8, Col 2).
  • Home Sanctuaries: Steps 52..57 are physically inaccessible to opponent players.

3.3 Turn Progression & Rule Algorithms

Extra Turn Rule: A player is immediately awarded a Bonus Extra Roll upon:
  1. Rolling a natural 6 (capped at 2 consecutive; 3 consecutive sixes forfeits turn).
  2. Capturing an active opponent token and sending it to Base.
  3. Guiding any token into the final Home Sanctuary Goal (Step 57).

3.4 Single Legal Move Auto-Movement Algorithm

To deliver an ultra-fast competitive experience matching Ludo Star, the engine computes legal moves upon every dice roll:

const legalMoves = getLegalMoves(gameState, currentSeat, rolledVal);

if (legalMoves.length === 1 && gameState.status === 'in_progress') {
  // Exactly 1 piece can move -> Auto-execute after 420ms animation window
  setTimeout(() => {
    gameService.movePlayerToken(legalMoves[0].tokenId);
  }, 420);
}

If legalMoves.length > 1, all valid tokens pulse with golden halos for manual player selection. If legalMoves.length === 0, turn automatically hands over to the next seat.

4. Multiplayer Networking & Room Protocols

4.1 Dynamic Multi-Player Room Engine (2P / 3P / 4P)

Unlike basic implementations that require 4 players or inject dummy bots, Royal Ludo dynamically supports custom player seating:

  • 2 Players Joined: The match operates strictly between Seat 0 and Seat 1 (or 0 and 2). Turn rotation alternates seamlessly (0 ↔ 1).
  • 3 Players Joined: The engine registers exactly the 3 seated players (0 → 1 → 2 → 0).
  • 4 Players Joined: Full 4-quadrant royal tournament.

4.2 Supabase Realtime Synchronization Protocol

All client actions are broadcasted over dedicated WebSocket channels:

Channel Event Type Payload Data Handler Action
match_room_CODE ROLL_DICE { seat: number, diceValue: number, timestamp: number } Executes deterministic dice roll on all guest screens simultaneously.
match_room_CODE MOVE_TOKEN { seat: number, tokenId: number, timestamp: number } Slides designated token with spring animation physics.
match_room_CODE EMOJI { seat: number, message: string, timestamp: number } Fires floating speech bubble and floating animated emoji reaction.
voice_CODE VOICE_SPEAKING { seat: number, isSpeaking: boolean, volumeLevel: number } Animates pulsing green wave ring around speaker portrait in real time.
voice_CODE VOICE_MUTE_STATE { seat: number, isMuted: boolean } Updates microphone mute badge state across all player panels.

5. Economy Modeling & Stake Wagering System

5.1 Betting Stakes & Prize Pool Logic

Matches can be played casually or staked with Imperial Treasury Coins. When a staked match begins:

  1. Each entering player's account is verified for sufficient balance (user.coins >= stakeAmount).
  2. The entry stake is deducted and locked into the match escrow pool (totalPot = stakeAmount × playerCount).
  3. The arena displays an active Live Prize Pot Badge.
  4. Upon victory, 100% of the pot is instantly transferred to the 1st place winner's vault.
